# Agent Harness 分步实验指南

配合 `agent_harness_demo.py` 使用。每个实验给出命令、预期轨迹和观察点，按顺序做完约需 30 分钟（不含等待模型响应）。

## 准备

1. 安装依赖：
```bash
pip install -r requirements.txt
```

2. 安装 LibreOffice（公式重算依赖，验证：`which soffice`）：
```bash
brew install --cask libreoffice
```

3. 配置 Key：仓库根目录 `.env` 中设置 `API_KEY` 与 `API_BASE`（OpenAI 兼容端点）。本仓库实测使用阿里云百炼专属 MaaS 端点 + 受限 Key（仅允许 `qwen3.6-27b`）。

## 实验 1：端到端跑通默认任务（核心实验）

```bash
python agent_harness_demo.py --model <你的模型> --base_url <你的端点>
```

默认任务：分析 `data/` 中的销售 Excel，产出 `report.md` + 带公式的 `output/report.xlsx`，并跑公式重算校验。

### 观察点：Skill 三层渐进式披露

| 层级 | 轨迹中的表现 | 原理 |
|---|---|---|
| 1. 元数据 | 轨迹中不可见 | 启动时系统提示词只注入 xlsx 的一句话 description，agent 凭它判断相关性 |
| 2. 指令 | `read_file({'file_path': 'skills/xlsx/SKILL.md'})`，打印 `<<< 第 2 层` 标记 | 模型判定任务匹配后主动读取完整 SKILL.md（约 9KB） |
| 3. 资源执行 | `execute_python` 内 subprocess 调用 `scripts/recalc.py`，返回 `"status": "success"` | 附属脚本不只是被读，而是被真正执行 |

### 观察点：harness 内置部件与错误自愈

- agent 会先 `glob`/`ls` 探查 `data/` 再读取——数据源靠"目录约定 + 自然语言描述"给出，具体文件由 agent 自行发现
- 中途大概率出现代码报错（`NameError`、路径拼错等），注意看 agent 如何从返回的异常栈中**自行修正重试**——这是 harness 把工具错误回传模型的循环设计
- 产物质量自检：打开 `output/report.xlsx`，应看到多个工作表、全部用 `SUMIF`/`SUMPRODUCT` 等真实公式（而非硬编码数值）——这是 SKILL.md 规范生效的直接证据

> 提示：用管道（如 `| tee`）运行时输出会缓冲，看不到实时轨迹属正常现象；可用 `ps aux | grep agent_harness` 或检查 `output/` 目录判断进度。

## 实验 2：验证 Skill 路由（负例）

换一个**不涉及表格产出**的任务：

```bash
python agent_harness_demo.py --model <模型> --base_url <端点> \
    --task "总结 data/ 目录里有什么数据，给出一段文字描述"
```

**预期**：轨迹中**不出现** `read_file('skills/xlsx/SKILL.md')`——agent 判断任务与 Skill 描述不匹配（description 明确写了"Do NOT trigger when the primary deliverable is a Word document..."），完整的 9KB 指令始终不进上下文。

**对比体会**：第 1 层披露只有一句话的成本，换来了"知识只在相关时占用上下文"——这就是渐进式披露相对"把所有知识塞进系统提示词"的核心优势。

## 实验 3：自定义任务与数据源

```bash
# 换分析角度（仍是表格产出，Skill 会被加载）
python agent_harness_demo.py --model <模型> --base_url <端点> \
    --task "分析各品类的销售占比，产出带公式的汇总表"

# 换数据文件：把新文件放入 data/，任务描述相应调整即可
python agent_harness_demo.py --model <模型> --base_url <端点> \
    --task "分析 data/ 中的 xxx.csv……"
```

数据源指定机制（三层配合，无硬编码传参）：

1. **物理层**：`FilesystemBackend(root_dir=本目录)`，`data/` 在 agent 文件系统视野内
2. **约定层**：系统提示词约定"data/ 是输入、output/ 是产物"
3. **任务层**：自然语言描述指向数据（可模糊如"data/ 中的销售记录"，也可精确到文件名）

> 提示：大文件（如几十万行 CSV）建议任务里要求先抽样或聚合，避免 pandas 输出撑爆上下文。

## 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| `403 Access denied by API-Key restrictions` | Key 在平台侧配了限制（模型白名单/IP 白名单/工作空间），`/models` 接口能通但调用被拒。到控制台核对该 Key 的限制配置；若是模型白名单，用允许的模型名重试 |
| `404 Model not exist` | 模型名不在该端点实际部署列表中（`/models` 返回的是全量目录，不代表都可用） |
| 运行时无输出 | 管道缓冲，见实验 1 提示 |
| `recalc.py` 报 `soffice not found` | 未装 LibreOffice 或不在 PATH |
| agent 调 `recalc.py` 路径报错 | 脚本须以 `skills/xlsx/scripts/` 为工作目录运行（其内部 `from office.soffice import ...` 的导入约定）；系统提示词已约定，若模型仍出错可观察它自我修正 |
| 产物公式单元格显示为空 | openpyxl 写公式无缓存值，必须经 recalc.py 重算——这正是要演示的坑 |
