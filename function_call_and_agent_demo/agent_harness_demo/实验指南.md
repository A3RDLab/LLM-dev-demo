# Agent Harness 分步实验指南

配合 `agent_harness_demo.py` 使用。每个实验给出命令、预期轨迹和观察点，按顺序做完约需 45 分钟（不含等待模型响应）。

## 准备

1. 安装依赖：
```bash
pip install -r requirements.txt
```

2. 安装 LibreOffice（公式重算依赖，验证：macOS/Linux 用 `which soffice`，Windows 见下方"Windows 用户注意"）：
```bash
# macOS
brew install --cask libreoffice
# Windows（PowerShell）
winget install TheDocumentFoundation.LibreOffice
# Linux（Debian/Ubuntu）
sudo apt install libreoffice
```

3. 配置 Key：仓库根目录 `.env` 中设置 `DASHSCOPE_API_KEY`（可选 `DASHSCOPE_BASE_URL` 指定专属端点）。默认模型为百炼 `qwen3.8-max`（多模态，读图实验依赖它），Key 需有该模型调用权限。若不用 `.env`，临时环境变量写法：macOS/Linux `export DASHSCOPE_API_KEY=xxx`；Windows PowerShell `$env:DASHSCOPE_API_KEY="xxx"`；cmd `set DASHSCOPE_API_KEY=xxx`。其他 OpenAI 兼容平台用 `--model/--base_url/--api_key` 覆盖。

### Windows 用户完整操作（PowerShell）

代码已针对 Windows 做了适配（LibreOffice 路径自动探测、控制台 UTF-8 输出），按下面步骤直接操作即可。未在 Windows 实机验证，遇问题先查文末"常见问题排查"。

```powershell
# 1. 安装依赖（需 Python 3.10+，从 python.org 下载或 winget install Python.Python.3.12）
cd function_call_and_agent_demo\agent_harness_demo
pip install -r requirements.txt

# 2. 安装 LibreOffice（无需手动配 PATH，脚本会自动探测常见安装位置）
winget install TheDocumentFoundation.LibreOffice

# 3. 配置 Key：仓库根目录 .env.example 复制为 .env，填入 API_KEY 与 API_BASE

# 4. 运行（注意两点：命令是 python 而非 python3；PowerShell 续行用反引号）
python agent_harness_demo.py --model <模型> --base_url <端点>

# 自定义任务示例：
python agent_harness_demo.py --model <模型> --base_url <端点> `
    --task "分析各品类的销售占比，产出带公式的汇总表"
```

Windows 适配细节（已在代码中实现，列出便于理解）：

| 问题 | 处理方式 |
|---|---|
| `soffice.exe` 不在 PATH（winget 安装默认不注册） | 脚本启动时自动探测 `C:\Program Files\LibreOffice\program` 等常见位置并补入 PATH |
| 控制台默认 GBK，中文轨迹乱码/报错 | 脚本启动时强制 stdout/stderr 为 UTF-8 |
| 重算子进程输出解码 | 系统提示词约定 agent 调 recalc.py 时设 `PYTHONUTF8=1` |
| 官方 `soffice.py` 的 LD_PRELOAD shim | Windows 10 1803+ 原生支持 AF_UNIX socket，shim 不会触发，无需处理 |

进度查看：`tasklist | findstr python`，或直接看 `output/` 目录是否产出文件。若 LibreOffice 装在非标准位置且 recalc 报 `soffice not found`，手动把其 `program` 目录加入 PATH，或先跳过公式重算步骤（实验 1 观察点 1、2 不受影响）。

## 实验 1：端到端跑通默认任务（核心实验）

```bash
python agent_harness_demo.py --model <你的模型> --base_url <你的端点>
```

默认任务：分析 `data/` 中的销售 Excel，产出 `report.md` + 带公式的 `output/report.xlsx`，并跑公式重算校验。

### 观察点：Skill 三层渐进式披露

| 层级 | 轨迹中的表现 | 原理 |
|---|---|---|
| 1. 元数据 | 轨迹中不可见 | 启动时系统提示词只注入 xlsx 的一句话 description，agent 凭它判断相关性 |
| 2. 指令 | `read_file({'file_path': 'skills/xlsx/SKILL.md'})`，打印 `<<< 第 2 层` 标记 | 模型判定任务匹配后主动读取完整 SKILL.md（约 9KB） |
| 3. 资源执行 | `execute_python` 内 subprocess 调用 `scripts/recalc.py`，返回 `"status": "success"` | 附属脚本不只是被读，而是被真正执行 |

### 观察点：harness 内置部件与错误自愈

- agent 会先 `glob`/`ls` 探查 `data/` 再读取——数据源靠"目录约定 + 自然语言描述"给出，具体文件由 agent 自行发现
- 中途大概率出现代码报错（`NameError`、路径拼错等），注意看 agent 如何从返回的异常栈中**自行修正重试**——这是 harness 把工具错误回传模型的循环设计
- 产物质量自检：打开 `output/report.xlsx`，应看到多个工作表、全部用 `SUMIF`/`SUMPRODUCT` 等真实公式（而非硬编码数值）——这是 SKILL.md 规范生效的直接证据

> 提示：用管道（如 `| tee`）运行时输出会缓冲，看不到实时轨迹属正常现象；可用 `ps aux | grep agent_harness`（Windows：`tasklist | findstr python`）或检查 `output/` 目录判断进度。

## 实验 2：验证 Skill 路由（负例）

换一个**不涉及表格产出**的任务：

```bash
python agent_harness_demo.py --model <模型> --base_url <端点> \
    --task "总结 data/ 目录里有什么数据，给出一段文字描述"
```

**预期**：轨迹中**不出现** `read_file('skills/xlsx/SKILL.md')`——agent 判断任务与 Skill 描述不匹配（description 明确写了"Do NOT trigger when the primary deliverable is a Word document..."），完整的 9KB 指令始终不进上下文。

**对比体会**：第 1 层披露只有一句话的成本，换来了"知识只在相关时占用上下文"——这就是渐进式披露相对"把所有知识塞进系统提示词"的核心优势。

## 实验 3：自定义任务与数据源

```bash
# 换分析角度（仍是表格产出，Skill 会被加载）
python agent_harness_demo.py --model <模型> --base_url <端点> \
    --task "分析各品类的销售占比，产出带公式的汇总表"

# 换数据文件：把新文件放入 data/，任务描述相应调整即可
python agent_harness_demo.py --model <模型> --base_url <端点> \
    --task "分析 data/ 中的 xxx.csv……"
```

数据源指定机制（三层配合，无硬编码传参）：

1. **物理层**：`FilesystemBackend(root_dir=本目录)`，`data/` 在 agent 文件系统视野内
2. **约定层**：系统提示词约定"data/ 是输入、output/ 是产物"
3. **任务层**：自然语言描述指向数据（可模糊如"data/ 中的销售记录"，也可精确到文件名）

> 提示：大文件（如几十万行 CSV）建议任务里要求先抽样或聚合，避免 pandas 输出撑爆上下文。

## 实验 5：多模态读图（read_file 直接看图）

主模型为多模态（默认 `qwen3.8-max`）时，`read_file` 读图片返回的是图像本身（base64 content block），模型直接"看到"图——没有 OCR、没有转写文本的中间层。

```bash
# 5a. 描述信息图：数字识别准不准？
python agent_harness_demo.py \
    --task "用 read_file 读取 data/icbc_p013_infographic.jpeg，描述图表类型与关键数据"

# 5b. 双环饼图 → 结构化 JSON（图表识别的真实工作形态）
python agent_harness_demo.py \
    --task "用 read_file 读取 data/icbc_p033_pie_asset_structure.jpeg，把内外两环（2023/2024 年资产结构）的占比数据按 {\"chart_type\":\"pie\",\"series\":[{\"name\":\"年份\",\"data\":[{\"label\":\"\",\"value\":0}]}]} 的 schema 写入 output/chart.json，并用 execute_python 校验 JSON 合法"
```

**观察点**：

| 轨迹表现 | 原理 |
|---|---|
| `read_file` 图片后打印 `↳ 返回多模态内容：image(image/jpeg)，图像直接进入模型上下文` | deepagents 文件系统按扩展名走 base64 图像管线 |
| 模型回复中出现精确数字（对公客户 1,334.86 万户、绿色贷款超 6 万亿等） | 模型真的"看"了图，而非猜的——可对照原图抽查 |
| 5b 产出可解析的 `output/chart.json`，两个 series 各 6 条 | 看图 → 结构化是 skill 图表识别阶段的核心动作（如年报→知识库） |

**失败对照**：若 `--model` 换成纯文本模型（如 DeepSeek-V3），同一任务要么报错要么模型"看不见图"瞎编——多模态能力在模型，不在工具。

## 实验 6：给 agent 装一个新 skill（运行时安装 + 清单热刷新）

deepagents 官方只在会话启动时扫描一次 `skills/`；本 demo 的 `RefreshableSkillsMiddleware` 给 agent 加了 `install_skill` 工具，装完立即生效。

```bash
# 6a. 安装示例 skill 并读取其 SKILL.md
python agent_harness_demo.py \
    --task "用 install_skill 安装 skill_submissions/annual-report-to-kb.zip，安装成功后 read_file 它的 SKILL.md，用三五句话总结工作流程"
```

**观察点**：

| 轨迹表现 | 原理 |
|---|---|
| `install_skill({'source_path': 'skill_submissions/annual-report-to-kb.zip'})` 返回"当前 skill 清单：annual-report-to-kb, xlsx" | 安装 → 重扫 → `Command(update={"skills_metadata": ...})` 热更新 state |
| 紧接着的下一轮，模型主动 `read_file('skills/annual-report-to-kb/SKILL.md')`（第 2 层标记） | 清单是每次模型调用从 state 重新渲染的——装完即见，无需重启 |

**校验负例**（自行构造坏包放 `skill_submissions/` 再让 agent 装，观察可读的拒绝原因）：

```bash
# zip 里目录叫 foo/ 但 frontmatter name: my-skill → 拒绝并建议改名
# frontmatter 缺 description → 拒绝（deepagents 原生是静默跳过，安装器显式报错）
# zip 条目含 ../ → zip-slip 防护拒绝，skills/ 零残留
```

```bash
# 6b. 端到端：装好的 skill 真正干活（年报 PDF → 知识库；图片识别阶段控制在前 2 张）
python agent_harness_demo.py \
    --task "skills/annual-report-to-kb 已安装。按它的 SKILL.md 流程处理 ../../archive/PDF_RAG_demo/ICBC_2024_FYR.pdf，输出到 knowledge_base/，图表识别只做前 2 张，最后按验证清单报告通过情况"

# 6c. （选做）闭环：产出的知识库交给 wiki_kb 检索
cd ../../wiki_kb_agent_demo && python kb_agent.py --kb-dir ../function_call_and_agent_demo/agent_harness_demo/knowledge_base --once "工行 2024 年个人贷款余额是多少"
```

**对比体会**：第 3 层披露的完整形态——skill 的 `scripts/build_kb.py` 不只被读，还被 agent 通过 execute_python 真正执行（环境准备、参数拼装、输出核对都由 agent 编排）。

## 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| `403 Access denied by API-Key restrictions` | Key 在平台侧配了限制（模型白名单/IP 白名单/工作空间），`/models` 接口能通但调用被拒。到控制台核对该 Key 的限制配置；若是模型白名单，用允许的模型名重试 |
| `404 Model not exist` | 模型名不在该端点实际部署列表中（`/models` 返回的是全量目录，不代表都可用） |
| 读图任务模型"看不见图"或报错 | 主模型不是多模态模型——`read_file` 的图像管线要求模型本身能收图，默认 `qwen3.8-max` 可用，切回多模态模型即可 |
| `install_skill` 报"name 与目录名不一致/缺 description" | 按错误信息修 skill 包：frontmatter 的 `name` 必须等于目录名、`description` 必填；deepagents 原生对缺字段是静默跳过，安装器显式报错是刻意设计 |
| `install_skill` 报"skills/<name>/ 已存在" | 卸载即删除目录：`rm -rf skills/<name>/`，然后重装 |
| 运行时无输出 | 管道缓冲，见实验 1 提示 |
| `recalc.py` 报 `soffice not found` | 未装 LibreOffice 或不在 PATH；Windows 下脚本已自动探测常见安装位置，非标准安装需手动加 PATH，见准备阶段"Windows 用户完整操作" |
| agent 调 `recalc.py` 路径报错 | 脚本须以 `skills/xlsx/scripts/` 为工作目录运行（其内部 `from office.soffice import ...` 的导入约定）；系统提示词已约定，若模型仍出错可观察它自我修正 |
| 产物公式单元格显示为空 | openpyxl 写公式无缓存值，必须经 recalc.py 重算——这正是要演示的坑 |
