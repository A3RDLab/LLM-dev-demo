# 修复 .qoder 误入库的提交历史

## 问题

- `fdfd285` 误将 `.qoder/commands/`（4 个文件）与 `.qoder/skills/`（4 个 SKILL.md）共 8 个文件入库为已跟踪文件；
- `7c67857` 只是在 `.gitignore` 加了忽略规则，但 .gitignore 对已跟踪文件无效——当前仓库处于"声称忽略、实际跟踪"的矛盾状态；
- 用户已确认采用改写历史方式修复（force push 已获授权）。

## 修复步骤

### 1. 退回两个提交（保留改动在暂存区）

```bash
git reset --soft df09699
```

退回 fdfd285 + 7c67857，HEAD 回到着色提交 `df09699`，两个提交的全部改动进入索引。

### 2. 从索引剔除误入库文件（本地文件保留）

```bash
git rm -r --cached --quiet .qoder/commands .qoder/skills
```

剔除后索引应只剩 `.gitignore` 的最终改动。用 `git status --short` 核验：已暂存内容仅 `M .gitignore`；`.qoder/commands/`、`.qoder/skills/` 变为未跟踪且被新规则忽略（`git check-ignore` 验证）；`.qoder/specs` 不受影响（既不被忽略也不入库）。

### 3. 重做干净提交

```bash
git commit -m "chore: gitignore 忽略 .qoder/commands 与 .qoder/skills（保留 specs 等其他内容）"
```

### 4. 强制推送并验证

```bash
git push --force-with-lease origin master
```

使用 `--force-with-lease` 而非 `--force`，防止覆盖远端可能存在的新提交。

验证项：
- `git log --oneline -3`：HEAD 为新提交，父提交为 `df09699`，fdfd285/7c67857 消失；
- `git ls-files | grep qoder`：输出为空（无 .qoder 文件被跟踪）;
- `git status -sb`：本地与 origin/master 同步；
- 本地 `.qoder/commands`、`.qoder/skills` 文件仍存在于磁盘且后续改动不再出现在 git status。

## 假设

- 远端无其他协作者的新提交（个人教学仓库，force-with-lease 兜底）；
- `.qoder/specs` 等其余目录维持"不忽略、暂不入库"的现状，不做额外处理。
