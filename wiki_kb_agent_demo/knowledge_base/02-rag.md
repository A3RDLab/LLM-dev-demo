# RAG 检索增强生成

RAG（Retrieval-Augmented Generation）让大模型基于外部知识库作答，
解决两类问题：模型训练知识过期、私域知识模型从未见过。

## 标准流程

1. **离线索引**：文档切块（chunking）→ 调用 Embedding 模型转向量 → 存入向量库
2. **在线检索**：用户问题转向量 → 向量相似度召回 top-k 候选块
3. **增强生成**：把召回的文本片段拼入 prompt，让模型引用资料作答

## 分块策略

常见的切块方式：固定长度滑窗、按 Markdown 标题切分、按语义段落切分。
对 wiki 类知识库，**按标题层级切分**效果最好——每个 chunk 自带"章节路径"，
既保留上下文，又让检索结果可溯源。

## 召回与重排

向量召回追求高召回率（top-k 取大些），再用 rerank 模型对候选做精排，
把最相关的片段排在前面。两阶段检索（召回 + 精排）是生产环境的常见做法。

## 常见坑

- chunk 太大：向量语义被稀释，检索不准
- chunk 太小：上下文不足，模型答不全
- 不做引用溯源：无法验证答案来自哪份资料
