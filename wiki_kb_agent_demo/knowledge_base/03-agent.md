# Agent 与 Function Calling

Agent 的核心是：LLM 决定"调什么工具、传什么参数"，程序负责真正执行，
执行结果回填给 LLM，循环往复直到 LLM 给出最终答案。

## Function Calling 原理

1. 开发者把工具的 JSON Schema 随请求传给模型（`tools` 参数）
2. 模型判断需要调用工具时，返回 `tool_calls`（工具名 + 参数 JSON）
3. 程序解析 `tool_calls`，执行对应函数，把结果以 `role: "tool"` 消息回填
4. 再次请求模型；模型可能继续调用工具，或直接给出最终回复

这个"模型决策 + 程序执行"的循环就是 Agent 的最小实现。

## 工具设计原则

- **单一职责**：一个工具只做一件事（搜索、读取、计算分开）
- **参数简洁**：参数越少、含义越明确，模型调用越准
- **结果可读**：工具返回结果应该是模型能直接理解的文本

## 知识库 Agent 的典型工具组合

对知识库场景，经典组合是两个工具：

| 工具 | 作用 |
|---|---|
| `search_wiki` | 按问题向量检索 top-k 相关片段 |
| `read_page` | 读取某页面的完整内容（片段不够时补充上下文）|

搜索定位"哪里相关"，读取补充"完整细节"，两者配合覆盖粗到细的查询需求。
